Egg import compatibility
========================

Campfire converts supported Egg exports into immutable native Embers. Importing
does not install a game, execute a script, fetch an update_url, or contact image
registries. Successful conversion is not a certification that a game or image
will run. Review the original script, selected image, port mappings, conversion
warnings and converted Ember before installing on a Spark.

Use Embers > Import Ember to upload a file, paste a definition, or load a public
HTTPS URL. Preview compatibility first. Blocking diagnostics must be resolved;
warnings require explicit acknowledgement. Import repeats conversion and
validation against the original definition rather than trusting the preview.
Each import receives a new Campfire ID; foreign UUIDs never update prior imports.

Format support matrix
---------------------
Input                              Status        Compatibility fixture
Native Ember schema 1              Supported     native.json; imported Eggs saved
                                                and read back as native JSON
Pterodactyl PTDL_v1                 Supported*    ptdl-v1.json
Pterodactyl PTDL_v2                 Supported*    ptdl-v2.json, extended.json
Pelican PLCN_v1                    Supported*    plcn-v1.json
Pelican PLCN_v2                    Supported*    plcn-v2.json
Pelican PLCN_v3 JSON               Supported*    plcn-v3.json
Pelican PLCN_v3 YAML               Supported*    plcn-v3.yaml
Unknown/missing export version     Blocked       parser rejection tests

* Supported subject to the feature matrix below, not complete Wings emulation.
All formats accept one JSON object or YAML document of at most 1 MiB. YAML
aliases, merges, custom tags, duplicate keys, multiple documents and non-finite
numbers are rejected. Nested config JSON strings and direct config objects are
accepted. Supported legacy formats can also be encoded as YAML.

Feature support matrix
----------------------
Feature                       Behavior
Image choices                 PTDL_v1 image/images; other versions docker_images.
                              No image is pulled while previewing/importing.
Startup command               Preserved with supported placeholders translated.
PLCN_v3 startup variants       A single command is automatic. Multiple commands
                              require explicit selection; alternatives are not
                              retained and a warning is shown.
Runtime conventions           /home/container, UID:GID 1000:1000. Existing image
                              ENTRYPOINT stays active. Campfire supplies STARTUP
                              and sh -c arguments. Image hooks and shell behavior
                              need review; this is not a Wings runtime clone.
Installer                     Image, literal script and sh/bash/ash entrypoint
                              preserved. Shell variables are provided in the
                              environment. Panel {{...}} script templates are
                              blocked. Scripts run with Campfire's existing
                              installer capabilities, not privileged host access.
Variables                     Environment name, scalar default, required and
                              user_editable retained. YAML boolean defaults
                              become strings true/false. Non-editable variables
                              are pinned to defaults even for administrators.
Hidden variables              Blocked when user_viewable is false or missing;
                              conversion must not expose hidden values.
Validation rules              required, nullable, string, integer, numeric,
                              boolean, min, max, between, size, in and one regex.
                              Rules may be pipe-delimited strings or arrays.
                              Bounds apply to character counts for strings and
                              numeric values for integer/numeric variables.
                              Boolean environment values are 0 or 1. Nullable
                              optional empty values skip further validation.
                              Decimal comparisons retain precision; source bounds
                              that cannot round-trip in the native numeric format
                              block import. Decimal exponents are capped at
                              +/-10000; integer values must fit signed 64 bits.
                              Choice lists are simple comma-separated values;
                              quoted/escaped CSV choices are blocked.
Regex validation              RE2-compatible expressions with /, ~, # or %
                              delimiters and optional i/m/s modifiers. Regex
                              alternatives containing pipes are preserved.
                              Lookarounds, backreferences, unsupported modifiers
                              (including u), and unknown rules block import.
                              Unicode/case-folding differences require review.
Built-in placeholders         SERVER_PORT, SERVER_IP, SERVER_MEMORY, SERVER_CPU,
                              SERVER_THREADS, SERVER_DISK and SERVER_SWAP; env.NAME,
                              server.build.env.NAME, server.build.environment.NAME
                              and server.environment.NAME for declared variables.
Allocation placeholders       server.build.default.port/ip and
                              server.allocations.default.port/ip are translated.
Memory placeholders           server.build.memory and server.build.memory_limit
                              become SERVER_MEMORY (allocated MiB).
                              server.build.cpu/cpu_limit become SERVER_CPU
                              (percentage: 100 = one CPU core).
                              server.build.threads becomes SERVER_THREADS
                              (empty: no CPU affinity is configured).
                              server.build.disk/disk_space become SERVER_DISK
                              (allocated MiB). server.build.swap becomes
                              SERVER_SWAP (0 MiB: runtime swap is disabled).
                              Built-ins are also shell environment variables
                              in installers and running game containers.
Port and address semantics    SERVER_PORT is the first container port, not the
                              host mapping. SERVER_IP is 0.0.0.0 in the container.
                              Exports cannot infer TCP/UDP mappings. These
                              differences always produce a review warning.
Other placeholders            Blocked, including config.docker.interface and
                              node/location metadata. Variables are not invented.
Properties config             Simple key=value replacements in existing files.
                              No full Java properties escape/continuation parser.
JSON/YAML config              Object/mapping roots; dot-separated nested keys,
                              numeric array indices (0–4095) and whole-component
                              * wildcards over existing objects/arrays. Paths
                              have at most 32 components. Missing exact paths
                              are created; wildcards require existing entries.
                              Non-null scalar replacements. String values stay strings,
                              including "001"; numbers and booleans retain types.
                              Quotes/newlines in substituted strings stay valid.
                              JSON numbers retain precision. YAML output preserves
                              scalar types but normalizes formatting and comments;
                              anchors, aliases, merges, custom tags, timestamps,
                              duplicate keys and multiple documents are rejected.
INI config                    Default keys or section.key; [section.with.dots].key
                              selects section names containing dots. Uses the INI
                              parser's quoting and serialization. Values must be
                              single-line; unrelated settings are retained.
Text/file config              Literal line-prefix replacements. Most-specific
                              prefix wins when prefixes overlap. Unmatched lines
                              are retained; missing prefixes are not appended.
                              Replacement values must be single-line.
Missing config files          Created with contained parent directories for
                              converted Eggs. Native Embers opt in with create:true.
                              JSON/YAML start from an empty mapping; other files
                              start empty. File and parent ownership is assigned
                              to the Ember user during install/start.
Configuration bounds          Input/output files are limited to 1 MiB. Template
                              expansion and structural work are bounded; template
                              values are substituted once, never recursively.
                              Each file replacement is atomic. The entire batch
                              is not a transaction. Symlinks/special files rejected.
Advanced config               XML, bracket array syntax, partial-component globs,
                              conditional/object replacements and null replacement
                              values still block import.
Readiness                     Up to 16 alternative literal substrings or /regex/
                              expressions with optional i/m/s flags. Regexes use
                              Go RE2 and match individual log lines; lookarounds,
                              backreferences and unsupported modifiers are blocked.
                              strip_ansi removes CSI/OSC terminal escapes before
                              matching. userInteraction string markers are omitted
                              with an informational notice; messages remain visible
                              in the console without special highlighting.
                              Placeholders are blocked. Detection uses the latest
                              200 log lines.
Stop command                  Literal or variable-expanded stdin command, or
                              ^C or a Docker Linux signal such as ^SIGTERM,
                              ^SIGABRT, ^SIGQUIT or ^SIGKILL. Signal names are
                              case-insensitive; the SIG prefix is optional.
                              Real-time signals support RTMIN, RTMIN+1..15,
                              RTMAX-14..1 and RTMAX (with optional SIG prefix).
                              Explicit signals override the image STOPSIGNAL;
                              an empty stop uses the image default. Docker
                              allows 30 seconds before force termination.
                              Substitution uses the declared
                              variables and built-ins, not a shell. Expanded
                              commands must be one line of at most 1024 bytes.
                              Unknown signals are rejected, never substituted
                              with a different signal. Commands go to stdin,
                              without shell evaluation.
Logs                          Container stdout/stderr. Custom log tailing blocked.
File denylist                 Non-empty denylist blocked; no silent access change.
Inherited definitions         Intentionally unsupported; not planned.
                              Unresolved config_from/copy_script_from blocked;
                              export a self-contained definition instead.
External mounts/privilege     Mounts, privileged installers and forced outgoing
                              addresses block import.
Panel feature integrations    eula, java_version, steam_disk_space and pid_limit
                              produce warnings. No EULA is accepted automatically,
                              no Java image is selected automatically, and
                              Campfire retains its own resource/process limits.
                              Other feature flags block import.
Presentation metadata         Source version, author, update URL and compatibility
                              warnings retained in origin metadata. Icons, tags,
                              widget types, display names and descriptions of
                              individual variables are not panel UI integrations.
Unknown fields                Blocked instead of silently dropping new behavior.

API and upgrades
----------------
POST /api/v1/embers/preview accepts a raw definition object, or a JSON envelope:
  {"definition":"<JSON or YAML text>","startup_command":"Default"}
It returns format, definition, ember (or null), warnings, errors, startup_commands.
Warnings marked informational:true are conversion notes and do not require
acknowledgement. The import screen collapses these under Conversion details.
Preview responses with blocking diagnostics still return HTTP 200 for review.
POST /api/v1/embers/preview-url accepts {"url":"https://.../egg.yaml"} and optional
startup_command. It uses the same conversion and existing public-HTTPS fetch
restrictions, including redirects and resolved address checks.
POST /api/v1/embers accepts the same definition envelope plus
acknowledge_warnings:true. Invalid/unacknowledged imports return HTTP 400 and
create no Ember. Raw native definition POSTs continue to work. All three routes
require an authenticated administrator and the existing CSRF checks.

Native definitions and converted Eggs use Ember schema 1. Extended configuration,
readiness and stop behavior are part of that schema and are validated on Spark
as well as Campfire. Such definitions require the negotiated Spark capability
server.ember.behavior.v1; older Sparks reject configuration delivery explicitly.
The database schema and Spark wire protocol are unchanged by these additions.

Native schema 1 uses configs[].create to opt into missing-file creation and
configs[].parser values json, yaml, ini, file or properties. Structured config
values use dot paths; configs[].strings forces selected replacements to remain
strings. Omit ready when using the extended readiness object, for example:

  "readiness": {
    "any": [
      {"value":"Ready for connections"},
      {"value":"^Listening on port [0-9]+$","regex":true}
    ],
    "strip_ansi": true
  }

Stop templates use ordinary native placeholders such as "quit {{STOP_REASON}}".

Fixture scope and references
----------------------------
Fixtures live in backend/internal/campfire/service/testdata/eggs. They are small,
synthetic examples exercising export shapes and known runtime limitations, not
redistributed upstream game installers. unsupported.json covers blocked runtime
and security features. Automated tests also cover rule bounds, aliases, malformed
documents, URL parity, warning acknowledgement, immutable import revisions,
administrator access, server creation and Spark-side validation. Runtime tests
verify JSON/YAML nesting, array/wildcard bounds, INI/text rewrites, missing file
creation, unsafe YAML/path rejection, precision, terminal escape removal,
readiness regexes/alternatives, stop-template injection rejection and capability
gating. Remote tests deliver extended definitions and rewrite files over the
authenticated Spark connection. These tests do not download or launch Minecraft,
Steam games, or external images.
